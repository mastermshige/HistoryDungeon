# Unity × AI ゲーム開発テンプレート

Unityでゲームを作るための **テンプレート（原本）** です。
AI を **秘書** として窓口に立て、「企画 → 設計 → 実装」を会話しながら進めます。
クラス名や置き場所を指定しなくても、自然言語で依頼するだけで設計の整ったコードが積み上がることを目指しています。

---

## このテンプレートでできること

- **秘書ワークフロー**: AI が秘書として、企画の壁打ち → 仕様化 → 実装まで伴走します。
- **設計が崩れにくい土台**: MVP（パッシブビュー）と asmdef による層分離を前提にしているため、初心者でも保守しやすい構成になります（詳細は `CoreRules.md`）。
- **自然言語での依頼**: 「スコアを増やす仕組みを作って」のように伝えるだけで、AI が適切な層・名前で配置・実装します。
- **その場で動作確認**: uLoop（MCP）でコンパイル・テスト・プレイ確認を自動で回し、「直したら確かめる」を徹底します。

---

## 前提環境

- Unity **6.3系**（目安は 6.3.8。6.3.x であれば別の番号でも構いません。番号のズレは秘書が自動で合わせます）
- 必須アセット
  - **UniTask** … 非同期処理（待ち・タイマー・キャンセル）
  - **DOTween** … アニメーション・演出（無料版で可）
  - **uLoop ＋ MCP** … AI から Unity を操作して検証を自動化する仕組み

> **アセットは本テンプレートに同梱していません。** UniTask と uLoopMCP は `Packages/manifest.json` の記載に従って Unity が自動取得します。
> **DOTween（無料版）だけは Asset Store から各自インポート** してください（ライセンス上、本テンプレートには同梱できません）。インポート前はアニメーション関連がコンパイルエラーになりますが、導入後に解消します。

> レンダーパイプライン（URP / Built-in）や Input System の設定は、プロジェクトごとに `CLAUDE.md` の環境設定欄で指定します。

---

## クイックスタート

1. このテンプレートを複製し、新しいゲーム用のプロジェクトとして開きます。
2. プロジェクト直下で Claude Code を起動します。
3. 秘書が起動し、初回は次の順でオンボーディングを案内します。
   - 秘書キャラの決定 → オーナープロフィール → 企画の壁打ち → プロジェクト名 → 仕様（Spec）化
4. 以降は実装フェーズに入り、機能を1つずつ積み上げていきます。

2回目以降は、秘書が「前回どこまで進んだか・今日は何をするか」を共有してから作業を始めます。

## ファイル構成

| パス | 役割 |
|---|---|
| `CLAUDE.md` | AI が最初に読む入口。全体の道案内 |
| `CoreRules.md` | 全ゲーム共通の設計・コーディングの約束（実装前に必読） |
| `Secretary/Secretary.md` | 秘書の振る舞い・進行管理ルール |
| `Templates/Concept_template.md` | 企画書の雛形 |
| `Templates/Spec_template.md` | 実装仕様書の雛形 |

ゲームを進めると、以下が生成・更新されます。

| パス | 役割 |
|---|---|
| `Secretary/Owner.md` | 秘書キャラ設定＋オーナープロフィール＋プロジェクト名 |
| `Concept.md` | 固めた企画 |
| `Spec.md` | 実装仕様 |
| `Secretary/Tasks.md` | これからやること |
| `Secretary/History.md` | 開発履歴 |

---

## 役割分担の考え方

- **共通の約束**（設計・書き方）は `CoreRules.md` にまとめます。どのゲームを作っても変わりません。
- **そのゲーム固有のこと**（素材・ルール・数値・画面）は `Spec.md` に書きます。
- この2つを組み合わせることで、共通ルールを保ちながらゲームごとの中身を差し替えられます。
